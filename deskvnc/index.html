One client for VNC, RDP and SSH

DeskVNC keeps all three kinds of host in one library. It has its own protocol cores, written in Rust: VNC from RFB 3.3 to 3.8 with VeNCrypt, RA2 and Apple authentication, RDP with NLA and RemoteApp, and SSH with SFTP, tunnels and PuTTY key files. The interface runs in Tauri 2.

Let an AI agent drive a desktop

The app ships dvv, an MCP server. An agent can open a saved machine, look at the screen, click, type, move files, open an SSH terminal and work on groups of machines. Leases and stale screen fences stop it from acting on a screen it has not seen. The source registers about two dozen dvv_ tools.

Nothing is installed on the target. The agent uses the same VNC, RDP or SSH connection a person would, and a person can click into the pane and take control back at any time.

Questions

Does DeskVNC need an agent installed on the remote machine?

No. It connects over ordinary VNC, RDP or SSH, so the target only needs the server it already runs for those protocols.

Which AI clients work with the dvv MCP server?

The README lists Claude Code and OpenCode as verified, over both stdio and HTTP.

Is DeskVNC free?

Yes. The source is on GitHub under MIT or Apache 2.0, and release builds are on the releases page.
